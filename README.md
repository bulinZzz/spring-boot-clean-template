# spring-boot-clean-template

一个侧重于架构解耦的 Spring Boot 基础模板。

本项目的核心目的是通过建立严格的物理边界，将基础工具类与第三方服务隔离于核心业务逻辑之外，为后续的业务开发提供一个纯净、标准的基础骨架。

## 目录结构

项目在基础包 `com.xingyun.template` 下采用防腐层架构设计，主要包含以下分层：

*   **`core` (核心机制层)**
    提供项目运行所需的基础支撑，包括统一响应结构、全局异常拦截机制以及项目的基础配置。
*   **`util` (工具防腐层)**
    对常用的数据处理和基础操作进行统一封装。业务层应当仅依赖此层的封装接口，避免与特定的底层实现强绑定。
*   **`integration` (第三方服务层)**
    外部系统对接的隔离区。所有外部服务的调用与底层细节均在此处完成抽象与封装，对内仅暴露标准接口。
*   **`module` (业务模块层)**
    纯粹的业务逻辑实现区域。建议按具体的业务领域（Domain）划分子包。

## 快速开始

1. **创建项目**：在 GitHub 仓库主页点击 `Use this template` 按钮，生成全新的独立项目。
2. **重命名包**：使用 IDE 打开项目，选中根包名 `com.xingyun.template`，执行重命名操作（`Shift + F6`）将其修改为实际业务相关的包名。
3. **按需扩展**：根据实际业务需求，在 `util` 和 `integration` 包下添加所需的底层封装实现，随后在 `module` 层开展业务开发。

## 开发建议

为了维持项目的整洁与低耦合，建议在后续开发中参考以下原则：

*   **工具类隔离**：`module` 业务层应保持代码纯净，避免直接引用第三方工具库或外部 SDK。通用操作需通过 `util` 层的封装接口完成。
*   **异常处理规范**：`core` 层已内置全局异常拦截机制。推荐将标准业务异常抛出并交由全局接管，以保证响应结构的统一；对于需要精细化流控的特定场景，可自主进行局部捕获。
*   **外部接口防腐**：外部系统或第三方 API 的调用，须在 `integration` 层进行本地化抽象与封装。严禁外部接口的底层实现细节穿透到核心业务逻辑。
